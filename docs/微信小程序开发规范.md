# 微信小程序开发规范

> 适用范围：本仓库原生微信小程序（Skyline 渲染 + glass-easel 组件框架）。
> 基础库：`3.17.2`（以 `project.private.config.json` 的 `libVersion` 为准）。
> 目标：统一目录、命名、页面/组件写法、样式、接口、性能与发布流程，降低协作成本和线上风险。

---

## 1. 技术栈与约束

| 项 | 约定 |
| --- | --- |
| 开发方式 | 原生小程序，不引入 Taro / uni-app |
| 渲染器 | Skyline（`app.json` 中 `renderer: "skyline"`） |
| 组件框架 | glass-easel |
| 样式 | `style: v2`，尺寸优先用 `rpx` |
| 导航 | 自定义导航栏（`navigationStyle: custom`），复用 `components/navigation-bar` |
| 语言 | JavaScript（ES6+），暂不启用 TypeScript |
| 基础库 | ≥ 3.0.0（Skyline 配置已声明） |

新增能力前先确认基础库兼容性，避免使用未覆盖机型的 API。

## 2. 目录结构

```text
.
├── app.js / app.json / app.wxss
├── sitemap.json
├── project.config.json
├── project.private.config.json      # 个人/本机配置，勿把本地调试开关当规范
├── pages/                           # 页面，按业务分包
│   └── index/
│       ├── index.js
│       ├── index.json
│       ├── index.wxml
│       └── index.wxss
├── components/                      # 可复用组件
│   └── navigation-bar/
├── utils/                           # 纯函数、请求封装、校验、常量
├── services/                        # 按业务域拆分的接口层
├── stores/                          # 全局状态（如需）
├── assets/                          # 图片、图标、字体（控制体积）
│   ├── images/
│   └── icons/
├── config/                          # 环境、常量、主题
└── docs/                            # 规范与说明
```

规则：

- 页面只放 `pages/`，组件只放 `components/`，禁止互相混放。
- 一个页面/组件目录内必须四件套齐全：`.js` `.json` `.wxml` `.wxss`（无样式也保留空文件）。
- 业务接口不要写在页面里，统一进 `services/`。
- 工具函数不要依赖 Page/Component 实例，放 `utils/`。
- 静态资源按用途分子目录，禁止把大图直接丢在页面目录。

## 3. 命名规范

### 3.1 文件与目录

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 页面目录 | kebab-case | `pages/user-profile/` |
| 组件目录 | kebab-case | `components/goods-card/` |
| 页面/组件文件名 | 与目录名一致 | `goods-card.js` |
| 工具/服务文件 | camelCase 或 kebab-case，仓库内保持一种 | `request.js`、`user-service.js` |
| 图片 | 小写 + 连字符，带尺寸或用途后缀 | `home-banner-750.png` |

### 3.2 代码标识符

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 变量 / 函数 | camelCase | `fetchOrderList` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 组件名（json / wxml） | kebab-case | `navigation-bar` |
| 自定义事件 | kebab-case | `bind:add-cart` |
| data 字段 | camelCase | `isLoading` |
| CSS 类名 | kebab-case，组件加前缀 | `nav-bar__title`、`goods-card` |

布尔值用 `is` / `has` / `can` 前缀：`isLoading`、`hasMore`、`canSubmit`。

## 4. 配置规范

### 4.1 app.json

- `pages` 数组第一项为小程序首页。
- 新页面必须先在 `app.json`（或对应分包 `pages`）注册，再开发。
- 继续使用自定义导航：页面不要擅自改回系统导航，除非产品明确要求。
- 保持 `lazyCodeLoading: "requiredComponents"`。
- 分包：按业务域拆，单个主包控制在合理体积内（建议主包 < 2MB，整包按平台上限）。

分包示例：

```json
{
  "pages": ["pages/index/index"],
  "subPackages": [
    {
      "root": "pages/order",
      "name": "order",
      "pages": ["list/list", "detail/detail"]
    }
  ],
  "preloadRule": {
    "pages/index/index": {
      "network": "all",
      "packages": ["order"]
    }
  }
}
```

### 4.2 页面 json

- 只用到的组件才写入 `usingComponents`。
- 组件路径用绝对路径：`/components/navigation-bar/navigation-bar`。
- 不在页面 json 里堆全局配置能覆盖的项。

### 4.3 隐私与 sitemap

- `sitemap.json` 按产品要求配置收录；默认不要无脑全部 `allow`。
- 涉及用户信息、位置、相册等，必须配置隐私协议并在调用前说明用途。

## 5. 页面开发规范

### 5.1 基本结构

页面按生命周期分区书写，顺序固定：

```js
Page({
  data: {},

  onLoad(query) {},
  onShow() {},
  onReady() {},
  onHide() {},
  onUnload() {},

  onPullDownRefresh() {},
  onReachBottom() {},
  onShareAppMessage() {},

  // 事件处理
  onTapXxx() {},

  // 私有方法
  _loadData() {},
})
```

### 5.2 data 与 setData

- `data` 只放视图真正用到的字段。
- 禁止把函数、定时器、复杂运行时对象放进 `data`。
- `setData` 只传变化字段，禁止整对象无差别覆盖。
- 列表更新尽量改具体路径，例如 `list[0].status`，避免整表重绘。
- 高频场景（滚动、拖拽、动画）不要每次手势都 `setData`，做节流或改用 Skyline 支持的方案。

```js
// 好
this.setData({ 'order.status': 'paid' })

// 差
this.setData({ order: this.data.order })
```

### 5.3 生命周期

- 请求放 `onLoad` / `onShow` 时要分清：参数初始化用 `onLoad`，每次可见都刷新用 `onShow`。
- `onShow` 里的请求必须可重入，避免重复弹窗、重复计数。
- 页面卸载时清理定时器、监听、临时文件。
- 不要在 `onLoad` 里假设 DOM 已渲染完成；需要节点信息时放到 `onReady` 或 `wx.nextTick` 之后。

### 5.4 路由

| 场景 | API |
| --- | --- |
| 保留当前页 | `wx.navigateTo` |
| 关闭当前页 | `wx.redirectTo` |
| 回到已有页 | `wx.navigateBack` |
| Tab 页 | `wx.switchTab` |
| 清空栈并打开 | `wx.reLaunch` |

- 页面路径不要写死散落各处，集中到 `config/routes.js`。
- 传参只走 query，值要 `encodeURIComponent`；禁止传超长 JSON。
- 复杂数据用全局 store / 事件通道 / 缓存，不塞 URL。
- 返回上一页刷新：优先上一页 `onShow` 拉取，或 `EventChannel` / 全局事件。

## 6. 组件开发规范

### 6.1 何时抽组件

满足任一条件就抽：

- 两处及以上复用
- 结构独立、页面因此明显变短
- 需要独立生命周期或对外事件

不要为了「看起来整洁」把一次性结构拆成组件。

### 6.2 组件写法

```js
Component({
  options: {
    multipleSlots: true,
    styleIsolation: 'isolated',
  },
  properties: {
    title: { type: String, value: '' },
    visible: { type: Boolean, value: false },
  },
  data: {},
  lifetimes: {
    attached() {},
    detached() {},
  },
  methods: {
    onClose() {
      this.triggerEvent('close')
    },
  },
})
```

规则：

- 对外属性用 `properties`，内部状态用 `data`。
- 属性必须声明 `type` 和 `value`。
- 样式隔离默认 `isolated`，不要轻易 `apply-shared`。
- 自定义事件只冒泡业务结果，不把内部实现细节抛出去。
- 组件不要直接 `wx.navigateTo` 到具体业务页（导航栏「返回」这类通用行为除外）；业务跳转交给页面。
- 通用导航栏继续使用 `components/navigation-bar`，新增页面默认接入，不要每个页面自己写一套胶囊适配。

### 6.3 插槽与外部样式

- 多插槽必须在 `options.multipleSlots` 开启。
- 允许外部微调时提供 `extClass` 或 `externalClasses`，不要为了改颜色复制整个组件。

## 7. WXML 规范

- 不用原生 `scroll-view` 以外的滚动容器硬撑全屏；Skyline 下列表优先 `scroll-view` + `type="list"`（与首页一致）。
- 条件渲染：简单切换用 `wx:if`；高频显隐用 `hidden`。
- 列表必须有 `wx:key`，且值为稳定唯一 id，禁止 `index` 当 key（列表会插入/删除时尤其禁止）。
- 事件绑定：`bind:tap` 用于普通点击；需要阻止冒泡用 `catch:tap`。
- 不要在 WXML 里写复杂表达式，计算放到 JS 的 computed 字段或方法里。
- 长列表考虑虚拟列表 / Skyline 列表能力，禁止一次渲染过大节点树。
- 图片必须设宽高，避免撑开布局；`mode` 明确写出。

```xml
<!-- 好 -->
<view
  class="goods-card"
  wx:for="{{list}}"
  wx:key="id"
  data-id="{{item.id}}"
  bind:tap="onTapGoods"
>
  <image class="goods-card__cover" src="{{item.cover}}" mode="aspectFill" />
  <text class="goods-card__title">{{item.title}}</text>
</view>
```

## 8. 样式规范

### 8.1 单位与全局

- 间距、字号、圆角用 `rpx`。
- 1px 细线、阴影、固定设备像素场景可用 `px`。
- 安全区、导航高度用组件计算结果或 CSS 变量，禁止写死 `64px` 当导航高度。
- 全局只在 `app.wxss` 放真正全局的 reset / 布局基类。
- 页面样式不要污染全局；选择器避免标签选择器（`view`、`text`）无限制滥用。

### 8.2 写法

- 使用 class，不用内联 style 堆业务样式（动态值如导航适配除外）。
- BEM 或「块__元素--修饰」即可，同一组件内保持一致。
- 颜色、字号抽成 CSS 变量，集中在 `app.wxss` 或 `config/theme`：

```css
page {
  --color-primary: #07c160;
  --color-text: #111;
  --color-text-secondary: #666;
  --color-border: #eee;
  --font-size-title: 32rpx;
  --font-size-body: 28rpx;
}
```

- Skyline 不完全等同 WebView：先查当前基础库是否支持该 CSS，再使用 `position: sticky`、复杂滤镜、部分选择器。
- 首页已用 `page` 做纵向 flex + `scroll-view` 撑满，后续页面保持同一套页面骨架，避免每个页自己发明一种滚动结构。

### 8.3 适配

- 全面屏底部安全区：`env(safe-area-inset-bottom)`。
- 自定义导航必须使用胶囊按钮 `wx.getMenuButtonBoundingClientRect()`，与现有 `navigation-bar` 一致。
- 不要用 `wx.getSystemInfoSync` 作为第一选择，优先用 `wx.getWindowInfo` / `wx.getDeviceInfo` / `wx.getAppBaseInfo`。

## 9. JavaScript 规范

### 9.1 基础

- 使用 `const` / `let`，禁止 `var`。
- 用 `async/await`，避免深层回调。
- 比较用 `===`。
- 函数单一职责，页面方法过长（建议 > 80 行）就拆私有方法。
- 私有方法以 `_` 开头：`_fetchList`、`_formatPrice`。
- 注释只写「为什么」，不写复述代码的「是什么」。
- 删除无用 console；提交前不要留 `console.log`。调试可用封装后的 `logger`，生产环境关闭。

### 9.2 错误处理

```js
async _loadDetail(id) {
  if (!id) return
  this.setData({ isLoading: true })
  try {
    const detail = await getOrderDetail(id)
    this.setData({ detail })
  } catch (err) {
    wx.showToast({ title: err.message || '加载失败', icon: 'none' })
  } finally {
    this.setData({ isLoading: false })
  }
}
```

- 所有网络请求、支付、授权都要有失败分支。
- 用户可感知的失败用 Toast / 空状态页，不要只打日志。
- 禁止空 `catch`。

### 9.3 异步与时序

- 页面请求加简单防重（loading 锁或请求序号），避免乱序回写。
- 返回结果写 `setData` 前判断页面是否仍有效（可对比 `requestId` 或在 `onUnload` 置标志）。

## 10. 网络与接口规范

### 10.1 统一封装

所有 `wx.request` 必须走 `utils/request.js`，页面禁止直接调用。

封装必须包含：

- baseURL 按环境切换
- 超时时间
- header（含登录态）
- 统一错误码处理（登录过期、权限、服务端错误）
- loading 可配置，默认不全局转圈（避免列表刷新闪屏）
- 可取消 / 忽略过期请求（可选，但列表页建议做）

```js
// services/order.js
import { request } from '../utils/request'

export function getOrderList(params) {
  return request({
    url: '/orders',
    method: 'GET',
    data: params,
  })
}
```

### 10.2 约定

- 接口按业务域拆文件：`services/user.js`、`services/order.js`。
- 入参、出参在函数上方用简短注释说明关键字段。
- 不要在服务层 `setData` 或弹 Toast（登录失效等全局异常除外）。
- GET 用 `data` 传查询参数；上传文件走 `wx.uploadFile` 封装，不混进普通 request。
- 域名必须配入小程序后台 request 合法域名；本地可临时关 `urlCheck`，但不得把关闭检查提交为默认团队配置。

### 10.3 环境

```text
config/env.js
- develop   开发
- trial     体验
- release   正式
```

用 `wx.getAccountInfoSync().miniProgram.envVersion` 区分，禁止在业务代码里手写切换开关。

## 11. 状态、存储与登录

### 11.1 全局状态

- 真正全局（登录用户、定位城市）可放 `app.globalData` 或独立 store。
- 页面私有状态不要塞进 `globalData`。
- 跨页通信优先：上一页回刷、EventChannel、store；慎用 `getCurrentPages` 直接改上一个页面 `data`。

### 11.2 存储

| 类型 | 使用 |
| --- | --- |
| 登录态、轻量偏好 | `wx.setStorageSync` / 异步 API |
| 大对象、临时数据 | 内存 / 本次会话变量 |
| 敏感信息 | 不落本地明文 |

- 读写 key 集中定义，禁止魔法字符串。
- 存之前确认体积；不要把整页接口结果无过期地缓存。

### 11.3 登录与授权

- 登录态失效时统一跳转/静默续期，不要每个页面自己弹登录。
- 授权（位置、相册、摄像头）必须先说明用途，再调 API。
- 用户拒绝授权要有降级，不能卡死流程。

## 12. Skyline 与性能

本项目默认 Skyline，开发时注意：

- 优先使用官方在 Skyline 下已验证的组件和 CSS。
- 滚动容器用 `scroll-view`；首页模式（`page` 纵向 flex + `.scrollarea`）作为标准页面骨架。
- 避免 WebView 时代的 hack（大量 `cover-view` 叠层、依赖浏览器特性的 CSS）。
- `glass-easel` 下组件行为以官方文档为准，不要按旧自定义组件的边角差异去「试出来就行」。

性能清单：

- 控制 `setData` 频率和体积。
- 图片压缩、使用合适分辨率；能用 CDN 宽参就不要打包进小程序。
- 分包 + 预下载，避免首包塞业务页。
- 非关键代码按需引入。
- 列表分页，默认页大小与后端约定（如 10/20）。
- 避免在 `WXML` 中对超长列表做复杂 `WXS` 计算（若使用 WXS/Skyline worklet，需有注释说明原因）。

## 13. 安全规范

- AppSecret、商户密钥、仅服务端可持有的 token **一律不进小程序代码**。
- 接口鉴权以服务端为准，前端校验只用于体验。
- 用户输入展示用文本节点，注意富文本 `rich-text` 的内容来源。
- 不在日志、分享卡片、storage 中写入完整证件号、手机号等敏感信息。
- 支付、退款等资金操作必须服务端下单与验签。
- 上传代码前检查是否误提交 `.env`、私钥、测试账号。

## 14. 体验与交互

- 主按钮在底部时预留安全区。
- 点击热区不小于约 `64rpx`。
- 加载：骨架屏或局部 loading，避免整页白屏。
- 空状态、失败状态、无网络状态都要有。
- Toast 文案短、可执行（「加载失败」不如「加载失败，请稍后重试」）。
- 提交类按钮防重复点击。
- 分享：`onShareAppMessage` 明确 title、path、参数，path 必须可独立打开。

## 15. Git 与协作

### 15.1 提交

- 提交信息：`type: 摘要`，用中文或英文但仓库内统一。

| type | 用途 |
| --- | --- |
| feat | 新功能 |
| fix | 修复 |
| refactor | 重构 |
| style | 样式（不影响逻辑） |
| chore | 构建/配置 |
| docs | 文档 |

示例：`feat: 订单列表支持下拉刷新`

### 15.2 禁止提交

- `project.private.config.json` 中的个人偏好如需忽略，团队应约定是否入库。
- `node_modules`、本地证书、IDE 私有文件、超大原始设计稿。
- 调试残留：`debugger`、注释掉的大段代码、测试 AppId 误替换（以仓库 `project.config.json` 的 appid 为准）。

### 15.3 评审关注点

- 是否直接 `wx.request`、是否漏注册页面。
- `setData` 是否过大、列表是否缺 `wx:key`。
- 是否适配自定义导航和安全区。
- 是否处理失败与空态。
- 是否把密钥写进前端。

## 16. 开发、预览与发布

1. 开发版：开发者工具导入本项目，基础库与 `libVersion` 对齐。
2. 自测清单：真机（iOS + Android）各至少一台；开发者工具不能替代真机。
3. 体验版：提审前产品/测试验收。
4. 正式版：按后台流程提审；版本说明写清改动点。
5. 发版后观察错误日志与性能；紧急问题走热修流程（若有）。

本地调试：

- 可临时关闭域名校验，**合并代码前改回开启**。
- 不在 `app.js` 里留环境 hack。

ESLint：以根目录 `.eslintrc.js` 为准。后续应逐步打开 `eslint:recommended`，并把 `wx` / `Page` / `Component` 等保留为全局。新增规则需团队同意后统一加上。

```json
{

    "navigation-bar": "/components/navigation-bar/navigation-bar"

```
